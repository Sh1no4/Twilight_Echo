# Twilight Echo Plugin Developer Guide

This guide is the Phase 5 local-publishable path for third-party plugin authors.

## Quick Start

```bash
npx create-twilight-plugin init my-tool --type tool --id com.example.my-tool
cd my-tool
npm install
npm run build
npm test
npm run pack
```

Install the generated `.tep` from Settings -> Plugins -> Install directory /
`.tep`.

## Templates

- `tool`: subscribes to playback events.
- `provider`: registers a `MediaProvider` with search and playback URL hooks.
- `ui-tool`: registers a controlled PlayerBar button and command handler.
- `theme`: registers declarative CSS variables and a packaged stylesheet.

Native DSP plugins are not generated by the JS CLI. Use the C ABI documentation
and the Crossfeed ABI fixture as the DSP reference because DSP plugins run as
native code in the audio service.

## Typings

Use `@twilight-echo/plugin-api` for API v1 types:

```ts
import type { TwilightPluginContext } from '@twilight-echo/plugin-api'

export async function activate(context: TwilightPluginContext): Promise<void> {
  context.logger.info('Plugin activated')
}
```

## Packaging

`create-twilight-plugin pack` validates `plugin.json`, verifies `main` or
`binary` exists, excludes `node_modules` and common caches, then writes a `.tep`
zip package with `plugin.json` at the archive root.

## Static Index

The official index is `plugins.json` with `schemaVersion: 1`. Each entry repeats
the plugin manifest fields and adds:

- `sourceUrl`: `.tep` package URL or path relative to the index file.
- `checksumSha256`: sha256 of the `.tep` package.
- `repository` / `homepage`: source and documentation links.
- `tags`: search and category labels.
- `verified`: true only after manual review.

Index inclusion requires an open-source repository, README, truthful
permissions, a smoke test pass, and no runtime remote code loading.
