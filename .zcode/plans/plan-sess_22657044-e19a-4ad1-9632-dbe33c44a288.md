## Round 5：抽取播放历史控制器

### 目标
将 `usePlayerStore.ts` 中与播放历史写回直接相关的逻辑抽到 `src/renderer/src/stores/player/playbackHistoryController.ts`，保持现有 store 对外 API、播放加载顺序和持久化语义不变。

### 实施步骤
1. 新增 `createPlaybackHistoryController(options)` 工厂，采用现有 player controller 的注入式接口。
   - 注入 `currentTrack`、`currentTime`、`isPlaying` 等必要 refs。
   - 注入 `getPlaybackTime`、`seek`、`now` 等播放协调回调。
   - 通过窄接口注入书签服务和 podcast 进度服务，避免 controller 依赖 `usePlayerStore`。
   - controller 自己持有并返回稳定的 `resumeOffer` ref。
   - 暴露恢复书签、手动书签、播客进度回写、暂停/切轨触发和 `dispose()` 方法。

2. 保持现有触发时序。
   - `loadAndPlay` 在切换前继续使用已捕获的 `previousTrack`，先记录旧曲目恢复书签并强制写回旧播客进度。
   - 成功启动新曲目后再检查恢复书签。
   - cast/native/HTMLAudio 暂停路径继续执行恢复书签和强制播客进度写回。
   - `isPlaying` 与 `currentTime` watcher 继续由 store 负责监听，但调用 controller 的统一方法，避免重复注册运行时 watcher。
   - 播放速率偏好仍留在现有 playback-rate 逻辑中，不扩大本轮边界。

3. 从 `usePlayerStore.ts` 删除已迁移的模块级状态、函数和相关直接持久化调用，改为解构 controller 方法；保留原有 `resumeOffer`、`acceptResumeOffer`、`dismissResumeOffer`、`addManualBookmarkAtCurrentTime` 公共名称。

4. 新增 co-located `playbackHistoryController.test.ts`，并将其加入 `test:playback-routing`，覆盖：
   - 长曲目恢复书签阈值、最小位置和接近结尾过滤。
   - 异步加载后的旧曲目恢复书签不会因当前曲目变化而错误展示。
   - 恢复提示的接受、取消、曲目不匹配保护和 seek 调用。
   - 手动书签使用最新播放位置。
   - podcast 进度的非 podcast/no-op、节流、强制写回和切轨写回。
   - controller dispose 后不再提交异步恢复提示。

5. 更新现有源码契约测试，使涉及播放历史实现归属的断言指向新 controller；保留 store 层的集成契约，确认 controller 已被 module-scope 创建且公共 API 仍然导出。

6. 同步 `docs/agent-architecture-guide.md` 与 `docs/architecture-maintainability-action-plan.md`：记录 Round 5、controller 大小、`usePlayerStore.ts` 新大小及剩余音频输出拆分工作。
